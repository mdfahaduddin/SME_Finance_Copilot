About 60 seconds. Security is thirty percent of the score, so it is built into the architecture rather than the prompt. Three permission tiers mapped to roles, enforced on the server. Approving is something only a person can do in the app; there is no approve tool for the agent. Sign-in uses server-side sessions the browser's scripts cannot read, CSRF protection and optional two-factor codes. High-value approvals need the password again, and scheduled payments are capped, with both limits converted into the business's own currency so a taka business gets the same protection. Amounts are always read from the bill or invoice, so neither a client nor the model can change them. There is no tool that can send money to a new account, which is why the planted injection memo cannot succeed even if a model were fooled. And every request runs exactly once and expires after a day. The full threat model and our known-risk list are in the security self-assessment.
